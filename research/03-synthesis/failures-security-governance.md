### SG-1. Authorization is a paid tier, not a primitive

**Definition.** Document- and principal-level authorization in retrieval is delivered as a commercial tier, a managed-only feature, or an explicitly-documented customer responsibility — never as a property of the retrieval interface itself — so the deployments that need it most are the ones structurally denied it.

| Platform | Evidence (file → gist) | Corpus label |
|---|---|---|
| Databricks Vector Search | `datacloud-rag.md` SG-1 — vendor docs state column-level permissions are unavailable on Vector Search and that applications with ACL requirements **must implement them at the application layer**, on a product sold as "governance for free" | documented-recurring |
| Onyx | `oss-rag-platforms.md` S3 — document-permission sync is **Cloud/EE only**; the GitHub connector's per-user sync silently fails when a user's email is private: *"they will not get access to any documents"* | documented (vendor docs) |
| AWS Bedrock KB | `managed-aws-google.md` — document-level ACL filtering exists **only** in the 2026 Managed KB and **excludes the Web Crawler connector**; customer-managed KBs hand-roll tenancy from the same metadata filters that have per-store gaps and silent fallbacks | documented (docs) |
| Google Gemini File Search | same file — no per-user ACL story at all; stores are project-scoped, tenancy is metadata filters or store-per-tenant against a 10-store cap | documented (docs) |
| Haystack | `haystack.md` — RBAC is an **Enterprise Platform** feature; OSS has no document-level ACL model | documented (product tiering) |
| LightRAG family | `hkuds-lightrag-family.md` S2 — workspaces are the only tenancy primitive and **#2904** shows the `LIGHTRAG-WORKSPACE` header being *ignored in `/query`*, assembling context from the default workspace; no ACLs, no per-document permissions, no row-level security anywhere in the family | documented-recurring |
| Amazon Kendra (landscape) | `production-industry.md` §6a, verbatim — *"Customers are responsible for authenticating and authorizing user access."* The platform filters; the customer supplies identity; the seam is where ConfusedPilot-class bugs live | vendor docs |

**Inference-grade tail (same absence, weaker evidence, listed for completeness):** LangChain (`BaseRetriever.invoke(query)` carries no principal), LlamaIndex, DSPy, OpenAI vector stores (attributes are *filter hints, not security boundaries*), the six research toolkits (*"no tenancy, ACL, PII, or prompt-injection handling in any of the six codebases"*), the eight vector DBs/startup platforms (*"No platform in the group treats source-system ACL inheritance as a first-class, verifiable feature"*), the four low-code builders (n8n's Simple Vector Store: *"all users of the instance can access vector store data … regardless of the access controls set for the original workflow"*), RAGFlow (teams/KBs exist; no chunk-level ACLs propagate into retrieval), the ten agent frameworks (*"Mastra thread/resource IDs are namespaces, not authorization"*).

**Root cause.** Three forces point the same way. (1) **Open-core economics:** authorization is the ideal paywall feature — legally mandatory, expensive to build, and invisible in a demo. Haystack, Onyx, and Bedrock independently placed the boundary in the same place, which is what a shared incentive gradient looks like, not coincidence. (2) **A type signature that predates the requirement:** `retrieve(query, k) -> docs` has no argument for a principal, so authorization cannot be *expressed* in the abstraction and must be smuggled in as a filter (see SG-2). Every framework inherited this signature from single-corpus academic IR, where there is exactly one user. (3) **ACL correctness is unmeasured:** no retrieval benchmark scores "returned zero documents outside the caller's entitlement set," so a framework that ships ACLs gains nothing measurable, while a framework that ships better rerankers moves a leaderboard.

**Research context.** This is a non-adoption failure, not an open problem. `production-industry.md` §11.9 records **SD-RAG** (arXiv 2601.11199): human-readable policy constraints enforced *during retrieval, before data reaches the LM*, over a graph structure, reporting **~58% privacy improvement** over prompt-based enforcement. `private-federated-personalized.md` argues the required type explicitly: retrieval must be `(query, principal, policy) → (docs, provenance, privacy-cost)`, and notes no OSS framework exposes it. `cross-cutting-gaps.md`'s ownership table scores this row *standard/research exists: yes; framework primitive: **No***. The unsolved residue is narrow but real: pre- versus post-ranking filtering is undocumented by every vendor, and nobody publishes a recall guarantee for low-privilege users (**post-filter starvation** — filtering after top-k silently empties a low-privilege candidate list rather than erroring).

**Next-gen requirement.** The retrieval call must not compile without a principal, and entitlement enforcement must be a conformance test, not a tier. Testable: (a) `retrieve(intent, principal, policy, budget)` is the only public signature; (b) every store integration passes a mandatory suite asserting **zero documents outside the caller's entitlement set** — including the terminal-`NOT IN` case that fails open in LangChain4j #2513 and the operator-precedence case in Spring AI #3577; (c) the framework declares pre- or post-ranking filtering per backend and **reports low-privilege recall separately**, so post-filter starvation is visible; (d) ACL-propagation lag is a monitored SLA distinct from content freshness.

### SG-2. Tenant isolation rides the relevance-filter channel

**Definition.** Multi-tenant and per-user isolation is expressed as a metadata filter or a request header string travelling the same path as relevance filtering, so ordinary correctness bugs in filter translation, and ordinary string-interpolation bugs in filter handling, become authorization and injection vulnerabilities.

| Platform | Evidence (file → gist) | Corpus label |
|---|---|---|
| LightRAG | `hkuds-lightrag-family.md` S1 — **#2698**: `LIGHTRAG-WORKSPACE` header interpolated unsanitized into f-string Cypher; attacker could *"read, modify, or delete all data in the graph database"*; reporter noted private vulnerability reporting was **disabled** on the repo. S2 — **#2904** header ignored in `/query`; **#1927** per-instance PG workspace isolation bug; **#1835** cross-workspace incremental-update bleed | S1 single-anecdote / S2 documented-recurring |
| LangChain / LangGraph | `langchain-langgraph.md` S1 — **CVE-2025-67644** (CVSS 7.3): SQL injection **via metadata filter keys** in `langgraph-checkpoint-sqlite`. The filter channel *is* the injection channel | documented-recurring |
| LangChain4j | `jvm-js-ecosystems.md` — **#2513**: `.isNotIn` on PgVector generates `metadata->>'id' IS NULL OR … NOT IN (…)`, so appending it to any AND-chained filter *"will lead to all content being matched"* — i.e. tenant-isolation filters silently disabled (fails **open**). **#5906** (open): Coherence filters read the wrong metadata key | documented-recurring |
| Spring AI | same file — **#3577**: PgVector emits filters without parentheses, so `(a OR b) AND c` becomes `a \|\| b && c` (34 comments); **#1179** bad SQL for IN/NOT IN; **#3179** `VectorStoreDocumentRetriever` ignored the typed `Filter.Expression`; **#6422** S3Vectors delete-by-filter builds an invalid request | documented-recurring |
| RAGFlow | `ragflow.md` — **CVE-2025-25282**: IDOR enabling **cross-tenant** account listing/modification by any authenticated user; the file's own conclusion is that tenant isolation was enforceable at the app layer only | documented-recurring |
| Dify | `lowcode-builders.md` — broken-access-control cluster on a **multi-tenant** platform: CVE-2025-32790, -32795, -32796, -43862 (normal user edits app orchestration), -59422 | documented-recurring |
| R2R | `oss-rag-platforms.md` S1 — **#2292** cross-user conversation IDOR; **#2290** SQL injection in vector index management (`create_index`/`delete_index`); **#2295** `auth_wrapper` returns a **default admin superuser for unauthenticated requests**. All open, no maintainer response | documented-recurring |
| LlamaIndex | `llamaindex.md` — **#19370** (open, 33 comments): Azure AI Search OData filter not filtering chunks | documented |
| Flowise | `lowcode-builders.md` — **CVE-2025-29189**: SQL injection via `tableName` in `Postgres_VectorStores`, i.e. directly in the RAG path | documented-recurring |

**Root cause.** A metadata filter is a *relevance* construct that the ecosystem overloaded as a *security* construct, and the two have opposite failure requirements: a relevance filter should degrade gracefully and return something; a security filter must fail closed and return nothing. Underneath that sits a structural multiplier the JVM file names precisely — one portable filter DSL × ~20 backend converters = 20 independent places to reimplement the same semantics, with no conformance suite. And because these filters are ultimately serialized into backend query languages (SQL, OData, Cypher) by string construction, the same channel yields injection CVEs. OWASP LLM08:2025 already names the outcome: **cross-context leaks in multi-tenant environments**, embeddings from one group *"inadvertently retrieved in response to queries from another group's LLM."*

**Research context.** Genuinely under-served on both sides. The academic literature treats retrieval as single-tenant; the systems literature treats multi-tenancy as an infrastructure concern. `cross-cutting-gaps.md` shows filtered ANN — *which is what every multi-tenant, ACL'd, date-scoped enterprise query actually is* — is the least benchmarked and most fragile retrieval path (Qdrant documents that strict filters plus soft-deleted points can *"lead to disconnected graph components"*; payload indexes must be created **before** ingestion or the filter-aware edges never exist). The Big ANN NeurIPS'23 competition (arXiv 2409.17424) did add a filtered track; none of that has propagated into how frameworks configure or test filters.

**Next-gen requirement.** Isolation must be structurally separate from relevance, and filter translation must be a signed contract. Testable: (a) tenant/principal scope is a distinct, non-overridable parameter that cannot be expressed in, or overwritten by, the user-facing filter DSL; (b) a mandatory cross-backend conformance suite covers filter semantics, boolean types, null handling, operator precedence, and delete-by-filter, with **fail-closed** assertions — a translation error must produce an error, never a broader result set (at least one documented case, LangChain4j #2513, currently matches *all* content; Spring AI #3577 is a precedence break that can go either way); (c) no filter value ever reaches a backend query language by string interpolation — parameterized or typed construction only; (d) a red-team test asserts that no HTTP header, workspace ID, or thread ID is treated as an authorization token.

### SG-3. Retrieved content and memory are an unmediated instruction channel

**Definition.** Retrieved documents and stored agent memories are concatenated into the model's prompt with no structural separation between data and instructions and no trust mediation, so anyone who can write to the corpus or the memory store can write to the system prompt — and the only mitigations shipped are probabilistic filters, when they are shipped at all.

| Platform | Evidence (file → gist) | Corpus label |
|---|---|---|
| CrewAI | `agent-framework-retrieval.md` S1 — **#5057** (open): retrieved memory is concatenated directly into the system prompt; *"If memory entries have been poisoned (e.g., via indirect prompt injection through tool outputs), an attacker can inject arbitrary instructions into the system prompt of future agent interactions"* (OWASP ASI-01) | documented-recurring |
| Pydantic AI | same — **#5424** parallel memory-poisoning report (OWASP ASI06) | documented-recurring |
| MCP reference memory | same — **servers #4117** requests redaction and destructive-op guardrails; *"these are the templates the MCP ecosystem copies"* | documented-recurring |
| OpenAI / ChatGPT connectors | `managed-openai-azure.md` — **AgentFlayer** (Zenity, Black Hat USA 2025): one poisoned document shared into a victim's Drive makes ChatGPT search out API keys and exfiltrate them via image-markdown rendering, **zero-click**; the `url_safe` mitigation was shown bypassable | documented-recurring |
| Claude/ChatGPT connector fleet | same — PromptArmor tracked 2,517 connectors over six weeks: 37% changed, **21 read-only connectors gained write/delete**, **283 began injecting custom instructions into model context**, *"rarely with any notification or re-consent process"* | documented-recurring |
| NVIDIA RAG blueprints | `gpu-vendor-enterprise-rag.md` S4 — NeMo Guardrails is unsupported on **Helm** (the production deployment method), unavailable on **B200** (newest hardware), and unused by the **agentic** pipeline: three independent exclusions of the safety layer | documented-recurring (vendor docs) |
| Mem0 | `memory-and-localfirst.md` I11 — PII exclusion is expressed as *natural-language instructions to the extractor*; the launch-thread question was never answered: *"Do you just rely on the LLM to follow instructions perfectly?"* Prompt-level filtering has no enforcement, no audit, and no failure mode other than silent leakage | single-anecdote (pattern-forming) |
| LangChain | `langchain-langgraph.md` S2 — prompt-injection-via-retrieved-content has no framework mitigation; PII middleware addresses output redaction, not retrieval authorization; nothing prevents a retriever tool inside a `create_agent` loop from returning documents the user cannot see | architectural-inference |

**Landscape anchors (these convert the pattern from "framework smell" to "shipped critical bug"):** **CVE-2025-32711 / EchoLeak** in Microsoft 365 Copilot — NVD 7.5 HIGH, Microsoft **9.3 CRITICAL**, both vectors `PR:N/UI:N` (no privileges, no user interaction) — the formal statement of a zero-click attack on an enterprise RAG product. **Slack AI** exfiltration (PromptArmor, Aug 2024), where the vendor's response was that the behavior was *"intended."* **ConfusedPilot** (arXiv 2408.04870) names the right abstraction — the retriever is a **confused deputy**, acting with the user's authority on attacker-supplied content — and adds a second channel almost nobody discusses: *retrieval caches are a second data store with a weaker access-control model than the index they front.*

**Root cause.** The prompt is a single untyped string, so provenance information is destroyed exactly at the moment it becomes security-relevant. Simon Willison's **lethal trifecta** (private data + untrusted content + an outbound channel) is not a bug class in this ecosystem; it is the default architecture — an enterprise RAG assistant with a connector fleet and any email/webhook/MCP tool satisfies all three by construction. Two secondary forces keep it there: **no component owner accepts it** (Slack's "intended," and the composition being the vulnerability rather than any part), and **agent memory made the write path public** — memory is a corpus, so memory is a poisoning target, and the write is performed by the agent itself on content it just read.

**Research context.** The credible defences all exist and all make the same architectural move: **enforcement out of the prompt.** **CaMeL** (arXiv 2503.18813) does control-flow isolation plus capability-based access control at tool-call time: **77% of AgentDojo tasks solved with provable security vs 84% undefended** — a ~7-point utility tax for a *provable* guarantee, which is the single most important number in this dimension because it prices the alternative. **SD-RAG** (arXiv 2601.11199) does the same for disclosure, at the retriever. Contrast the filtering approach: the best layered filter in the 2026 set reports **ASR 71.4% → 11.3% at 4.8% FPR** — which, against Willison's standard that *"95% detection rates represent inadequate security standards,"* is a nuisance filter, not a boundary. **Two genuinely unsolved residues:** (i) *content-innocent attacks* — salience induction (arXiv 2607.17535, **83.3% ASR at a 30% edit budget** using truth-preserving edits, every claim true, no instruction present; the authors' own defence leaves **15.3–23.6%**) and document-authored control-signal impersonation (arXiv 2606.09005, attacker text masquerading as trusted metadata) defeat both fact-checking and injection-detection *structurally*; (ii) LogicPoison (arXiv 2604.02954) shows GraphRAG *extended* the surface, corrupting graph topology while every sentence stays plausible.

**Next-gen requirement.** A structural data/instruction boundary plus capability-gated action, budgeted like a resource. Testable: (a) retrieved text is a typed value that provably cannot reach the instruction position — asserted by a test that plants an imperative in a document and verifies zero behavioral change; (b) tool invocation after untrusted content enters context is capability-gated at call time, not classifier-gated, with the ~7-point utility cost from CaMeL as the accepted budget; (c) memory writes are quarantined with writer identity and trust tier recorded, and prior memory is a non-extractable provenance class (see SG-7); (d) retrieval **caches inherit the index's access-control model**, tested by a cross-principal cache-hit assertion; (e) the safety layer is available on every supported deployment path — a configuration in which guardrails cannot run must fail to deploy.

**Root cause.** Four mechanisms, all economic or architectural rather than accidental.

1. **The product feature *is* the vulnerability class.** A RAG framework's differentiators are: build prompts from templates (→ SSTI: Haystack, RAGFlow, Langflow), translate user filters into backend queries (→ SQLi: LangGraph-sqlite, Flowise, R2R, RAGFlow), serialize pipelines/configs so they can be shared (→ insecure deserialization: Haystack, langchain-core), ingest arbitrary documents from arbitrary sources (→ Zip-Slip, path traversal, SSRF: RAGFlow, IBM, AnythingLLM, DSPy), and let users run code inline (→ RCE: Langflow, n8n, Dify, RAGFlow). There is no version of these frameworks without those five surfaces, so hardening cannot be deferred to "later."
2. **Sandboxing arrives after exploitation.** RAGFlow's gVisor landed in v0.25, after the RCE classes were public. Haystack's allowlist landed in 3.0, after the whole 2.x era. AI-Q's *"Skills & Sandboxing: Support custom skills within isolated environments"* is still an **unchecked roadmap item**. The isolation cost is paid only once the class is exploited.
3. **Growth-first release cadence with no security gate.** These are pre-1.0-culture projects shipping weekly to a market rewarding feature velocity; LightRAG had **private vulnerability reporting disabled** (#2698) and R2R has no disclosure channel at all (#2297). Where the corpus can see a security process, it is a GitHub issue: NVIDIA's *"Nightly CVE Scan Tracker"* (#617, open).
4. **Adoption decouples from maintenance.** LangChain's CVE trio landed against ~84M weekly downloads; R2R's critical auth bug sits unanswered in a dormant repo still advertised as production-ready. Download counts, not security posture, drive procurement.

**Research context.** Almost entirely orthogonal to the academic literature, which is the finding. `cross-cutting-gaps.md` places category (a) *"between ML security and infrastructure"* — the adversarial-ML community studies poisoning and inversion while the actual incident stream is CWE-89/CWE-22/CWE-502/CWE-94 in the plumbing. The one bridging artifact is **SoK: The Attack Surface of Agentic AI** (arXiv 2603.22928), which systematizes prompt injection, KB poisoning, **and tool exploits** together, and ships a deployment checklist. Nothing in the research corpus tells a framework author to parameterize a filter or sandbox a template — that is ordinary application security that this ecosystem skipped.

**Next-gen requirement.** The five RAG-specific surfaces must be closed by construction, not by review. Testable: (a) prompt assembly uses a non-evaluating template engine with no expression execution — an SSTI payload in a prompt variable is inert by test; (b) no filter, table name, workspace, or index identifier reaches a backend query language except through parameterized/typed construction, enforced by a lint gate in CI; (c) pipeline/config loading uses a declarative schema with a module allowlist and no arbitrary import, with a test loading a hostile config and asserting a refusal; (d) ingestion (archives, URLs, file paths) runs in a sandbox with a default-deny egress allowlist and canonicalized path checks, covering Zip-Slip and SSRF as regression tests; (e) any code-execution node is sandboxed on day one, and the framework ships with it **off** by default; (f) the project has a private disclosure channel and a published CVE-scan gate in release CI.

### SG-5. Erasure and audit are unavailable by construction

**Definition.** "Delete this document" and "show me exactly what was retrieved, for whom, when, under which policy" are the two primitives every data-protection regime requires, and no framework in the corpus implements either verifiably — deletion is a tombstone or an unimplemented feature, and the retrieval record either does not exist or degrades on the newest code paths.

| Platform | Evidence (file → gist) | Corpus label |
|---|---|---|
| Mem0 / memory cohort | `memory-and-localfirst.md` I11 — *"Erasure is architecturally unavailable"*: ADD-only store plus no deletion tombstones in the cohort's ingestion, so *"forget this"* has no reliable implementation path. The canonical docs page now states **new memories are added without overwriting or deleting existing memories**. Also: *"no per-memory access controls, no retention/expiry policies, no user-auditable data-flow guarantees, no consent record per stored inference"* | documented (vendor docs) + documented-recurring |
| OpenAI vector stores | `agent-framework-retrieval.md` D3 — official docs: *"search results may still include content from a removed file for a short period"* — a GDPR problem stated as a footnote | documented-recurring (official docs) |

| LightRAG | `hkuds-lightrag-family.md` P4 — deletion regenerates affected KG parts from cached extractions: **#985** deletion leaves inconsistent state; **#2567** orphan workspace nodes remain in Neo4j **after deleting all documents** | documented-recurring |

**Substrate evidence (why this is "by construction," not a backlog item).** `cross-cutting-gaps.md` (c): Elasticsearch's own docs state a deleted document *"is not immediately removed but instead soft-deleted and marked with a 'tombstone'"*, cleaned up only during segment merges — and force-merging to reclaim them degrades the index and breaks incremental snapshots. hnswlib exposes `markDelete`, a **soft delete leaving the vector in the graph**; the canonical request *"add ability to delete elements from HNSW graph"* (**#4**) was opened **2018-04-04** and the fetched page shows no resolution; #652 asks for a flag to *filter out* deleted IDs, i.e. they can still be returned. Pinecone: *"eventually consistent."* Compose that with **vec2text** (arXiv 2310.06816, EMNLP 2023: **92% of 32-token inputs recovered exactly**, including full names from clinical notes) and the conclusion is not rhetorical — *soft-deleted content is recoverable content*. (`private-federated-personalized.md` reports Ghost Vectors, arXiv 2606.18497, making exactly this claim for HNSW, but it is **[listing-only]** there; the load-bearing chain above is vendor docs + a peer-reviewed result, and that is what I rely on.)

**Root cause.** ANN indexes are *derived, immutable-segment, graph-structured* artifacts optimized for read-mostly workloads; true deletion means a rebuild, so every implementer chose the tombstone, and every layer above inherited it silently. On top of that: the erasure requirement arrives from **legal**, an owner with no commit access, while the framework's roadmap is set by practitioners optimizing demo-to-first-answer time. And the coupling is perverse — accumulated tombstones **degrade recall** (Qdrant: strict filters plus many soft-deleted points *"might still lead to disconnected graph components"*), so the high-churn corpora that receive erasure requests are exactly the ones whose retrieval quietly rots. The audit half fails for a distinct reason: retrieval became **non-deterministic** (LLM query planning, parallel subquery merging, semantic caching, silent platform-side ranker changes), and Microsoft states outright that *"precise reconstruction of a query or response isn't guaranteed."* You cannot prove erasure without a retrieval record, and you cannot produce a retrieval record for a process you cannot replay.

**Research context.** Deletion is one of the few places where the research is *also* short. `private-federated-personalized.md` lists **verified deletion in ANN indexes** as open problem #3: *"nobody has a production HNSW/IVF design with cryptographic or auditable erasure guarantees."* The literature's inversion is telling — *When Machine Unlearning Meets RAG* (arXiv 2410.15267) proposes RAG as the *mechanism* for forgetting (edit the knowledge base instead of the model) while the retrieval index is itself the thing that cannot be reliably unlearned; nobody has closed that circle. **SILO** (ICLR 2024) makes the datastore's headline governance advantage over parametric memory *instant removal and per-item opt-out* — a claim that silently depends on index internals actually forgetting, which they do not. On the audit side the requirement is now statutory and specific: the EU AI Act's main body applies as of **2 Aug 2026**, and 21 U.S.C. §360j(o)(1)(E)(iii) conditions non-device status for clinical decision support on the clinician being able to *"independently review the basis for such recommendations"* — a retrieval-architecture requirement written into statute. `medical-vertical-rag.md` states the needed artifact concretely: *"Audit trail as a data structure, not a log line"* — query, expansions, index version, candidates with scores, **rejected candidates with reasons**, reranker decisions, prompt, generation, per-claim verdicts, abstention, human action; immutable and queryable.

**Next-gen requirement.** Erasure and audit are one primitive: a verifiable record that makes verifiable deletion provable. Testable: (a) `erase(doc_id)` returns a **completion proof** enumerating deletions across index, cache, snapshot, replica, and every derived artifact (graph nodes, contextualized chunks, extracted memories), with a test asserting the vector is **unrecoverable** rather than merely un-returned — including under the one-to-many chunk projection Azure's soft-delete explicitly excludes, and including LightRAG-class orphan graph nodes; (b) tombstone debt is a monitored metric with a declared ceiling, alarmed as *both* a compliance and a recall regression; (c) every answer carries a replay handle resolving to a content-addressed corpus snapshot, pinned chunker/embedder/reranker versions, the recorded plan and merge order, the principal, and the candidates **rejected with reasons** — and replay is byte-identical or the framework reports why not; (d) the audit record is emitted identically on every code path, with a test asserting the newest path (agentic/multi-hop) produces a record no weaker than the simplest one; (e) retention/expiry and consent basis are per-record policy fields evaluated at retrieval time, not application conventions.

**Research context.** No research fixes this; it is a market-structure failure, and the literature says so obliquer than it should. **Next-gen requirement.** Security posture must be a machine-checkable artifact of the deployment, not a page in the docs. ### SG-7. Retrieved content carries no trust label, and retrieval has no notion of corroboration

**Definition.** No framework attaches per-source provenance, authority, or trust metadata to retrieved chunks and memories in a way that propagates into ranking, prompt assembly, or tool gating — and top-k similarity retrieval has no concept of independent corroboration, so a single planted document is as authoritative as a consensus.

| Platform | Evidence (file → gist) | Corpus label |
|---|---|---|
| 10-framework agent cohort | `agent-framework-retrieval.md` S1 — *"No framework in the cohort ships provenance-tagged or trust-tiered memory"* (CrewAI, Pydantic AI, Mastra, smolagents, Letta, MCP servers, …) | documented-recurring |
| Mem0 / memory cohort | `memory-and-localfirst.md` — *"There is no provenance bit distinguishing 'user said this' from 'we previously stored this'"*; consequence: *"'User prefers Vim' was hallucinated once, then re-extracted 808 times through feedback loops"*; and #4573's **5.2% "hallucinated user profiles"** category means the memory layer *fabricates* personal data about identifiable subjects and later retrieves it as fact | documented-recurring |
| LightRAG family | `hkuds-lightrag-family.md` DP2 — **#239, #323, #469, #137** all request source attribution; chunk metadata absent, so *"filtering, provenance, and governance all suffer"* | documented-recurring |
| Haystack | `haystack.md` — chunk provenance metadata (`source_id`, `split_id`, `split_idx_start`, `_split_overlap`) is a *hidden contract* that several splitters silently violated (#12154, #11986), breaking downstream retrievers | documented-recurring |
| Spring AI | `jvm-js-ecosystems.md` — **#1167** (open): the splitter reassigns document IDs, breaking provenance and upserts | documented-recurring |
| DocsGPT | `memory-and-localfirst.md` I8d — README markets *"accurate, hallucination-free responses … with source citations"* while **#2106** "Add Citations to Responses" and **#1911** "Guardrails" remain open | documented-recurring |
| All managed platforms (landscape) | `production-industry.md` F14 — *"No reviewed platform exposes a per-source **trust level** that propagates into retrieval or tool-gating decisions"*, even as MCP industrialized the number of attached sources | vendor-docs survey |

**Root cause.** Provenance was designed as a *citation UX feature*, not a *security label*, so it is stored where UX needs it (a footnote at render time) rather than where enforcement needs it (attached to the chunk, surviving chunking, reranking, compression, and summarization). Three amplifiers: (1) chunking **destroys** identity by default — splitters reassign IDs and drop metadata, and no framework types the provenance contract, so it breaks silently; (2) similarity is the only ranking currency the abstraction exposes, so "prefer the label over the review article," "prefer the primary source," "prefer the non-retracted trial," and "require two independent sources" are all inexpressible; (3) retrieval-time **compression** (highlights, extracts, subagent summaries, context editing) discards evidence before the answering model sees it, and no reviewed system reports what was dropped — provenance is severed by an unaudited lossy transform inside the provenance chain.

**Research context.** The research here is unusually far ahead, in four separate literatures that frameworks have not read. **Poisoning:** PoisonedRAG (arXiv 2402.07867, USENIX Sec 2025) achieves **~90% ASR with five malicious texts per target question against millions of documents**, and evaluated defenses were *insufficient* — a ~1e-6 poisoning ratio that no manual review can catch, and whose deeper meaning is that top-k similarity **has no notion of corroboration**. AgentPoison (arXiv 2407.12784): **>80% ASR at <0.1% poisoning** of agent memory/KB. Phantom (arXiv 2405.20485): a *single* trigger-conditioned document, demonstrated against NVIDIA's shipped Chat with RTX. Jamming (arXiv 2406.05870, USENIX Sec 2025): a single blocker document silences a chosen topic, and the authors state existing safety metrics *"do not capture their vulnerability to jamming"* — an availability attack no eval harness measures. **Detection:** CleanBase (arXiv 2605.00460) flags similarity-graph cliques — but by construction it is blind to single-document jamming. **Source quality:** `aigc-contamination-geo.md` prescribes origin as a *soft, multi-signal, versioned* index field (never a hard filter — detectors misclassify non-native-English authors), credibility as a **multiplicative prior**, `score(q,d) = sim(q,d) × λ(source)` with λ as inspectable per-tenant data; origin-**diversity constraints enforced at exposure time** (because 67% pool contamination amplified to >80% exposure while accuracy metrics stayed acceptable); recency **gated on origin class**, because *"a freshness-weighted retriever is a contamination-weighted retriever"*; and derivative-chain detection as the highest-value untried mitigation. **Authority:** `medical-vertical-rag.md` shows the vertical that already codified this — evidence hierarchy (label > guideline > systematic review > RCT > cohort > case report > preprint), *upstream-of-gold* primary-source rate as a metric (DrugAudit's best system still misses ~8%), retraction tracking (Pub-Guard-LLM's 11K-article benchmark), and validity intervals rather than timestamps. **Arbitration:** `knowledge-conflict-attribution.md` warns the label must be *evidence metadata*, not model judgment — source preference is manipulable by mere repetition, and coherent fake evidence is persuasive. The 2026 attack literature closes the argument: because salience induction and metadata impersonation contain **no false statement and no instruction**, a trust label must attach to the **source**, not be inferred from the **content**.

**Next-gen requirement.** Provenance is a typed, propagating, enforcement-grade label, and corroboration is a retrieval-time constraint. Testable: (a) every chunk and memory carries an immutable record (source identity, writer, ingestion path, first-observed time, validity interval, authority tier, derivative-of link, versioned origin score) that survives chunking, reranking, compression, and summarization — asserted by an end-to-end test that the label on the answer's cited span equals the label at ingestion; (b) ranking accepts an inspectable per-source weight as **data, not code**, so authority and origin can be tuned per tenant and audited, including the weights' own provenance; (c) the retrieved set satisfies declared composition constraints — maximum share from one origin class, minimum independently-originated evidence, at most *k* derivatives of the same upstream document — enforced at **exposure** time, not pool time; (d) claims supported by a single source are typed as such and cannot silently answer a high-stakes query; (e) compression is a recorded, reversible-by-reference transform: what was dropped, under what policy, recoverable by a verifier; (f) the framework ships poisoning **and jamming** suites as pre-deployment gates, with availability (refusal-rate drift on a fixed topic set) as a monitored metric.

### SG-8. Egress is a default, not a decision

**Definition.** Data leaves the deployment's trust boundary through paths the operator did not choose — silent fallbacks to hosted APIs, on-by-default telemetry, and third-party knowledge sources — and no framework offers a verifiable no-egress mode, even though eliminating the outbound channel is the strongest available defense against the exfiltration chains in SG-3.

| Platform | Evidence (file → gist) | Corpus label |
|---|---|---|
| LlamaIndex | `llamaindex.md` S1 — **#20912**: *"if a developer misses injecting the local LLM into a nested retriever, the framework will silently attempt to send the user's private data/vectors to api.openai.com … If an old `OPENAI_API_KEY` happens to exist in the environment, the data leak occurs completely silently."* Cross-referenced to #19403, #17379, #18349, #20917. Maintainer response: *"This has been the standard in llamaindex for ages. It's well documented that things default to openai"* — closed as **intended behavior**; there is no strict/air-gapped mode. The mutable global `Settings` singleton compounds it (#8536, #8839, #16902) | documented-recurring |
| Khoj | `memory-and-localfirst.md` I11 — docs stated *"We do not log your IP address"* while the client IP was in the telemetry payload until **2026-08-02**, when PR **#1382** removed `client_host`; the launch thread also flagged telemetry **on by default** and possibly containing *"the API and chat queries"* — in a product whose pitch is a private second brain | single-anecdote (merged PR, primary) |
| Haystack | `haystack.md` — telemetry on by default (*"an event every time these components are initialized"*), drawing *"For an EU based company, this stands out"* | single-anecdote (primary) |
| Azure AI Search | `managed-openai-azure.md` — vendor-documented: remote/third-party knowledge sources *"might result in data processing or storage outside of the Azure compliance boundary"* | documented-recurring |
| Claude/ChatGPT connectors | same file — 21 read-only connectors silently gained **write/delete**; 283 began injecting instructions into context, *"rarely with any notification or re-consent process"* | documented-recurring |

*Honest weighting: the spine is LlamaIndex #20912 — stronger than its single-issue appearance suggests, because the maintainer closed it as intended behavior, making it a documented **design stance** rather than a bug. Khoj and Haystack are corroborating single-anecdotes with primary evidence (a merged PR; vendor docs). The structural claim below rests on `cross-cutting-gaps.md` (h), which is architectural-inference and labelled as such.*

**Root cause.** Framework defaults are set to minimize time-to-first-answer for a developer with a hosted API key, and hosted APIs are the path of least resistance for that. Global mutable configuration (LlamaIndex's `Settings` singleton) makes the default *reachable from anywhere* in a nested component tree, so egress becomes the failure mode of an omission rather than of an action. Telemetry is on by default because product analytics is an internal stakeholder with commit access while the privacy claim lives in marketing copy. And no-egress is not on any roadmap because *air-gapped deployment collides with the hosted-embedder business model*: `cross-cutting-gaps.md` (d)/(h) makes the coupling explicit — if your embedder is a hosted API you cannot be air-gapped and you do not control your own migration clock (Azure's 18-month GA clock ends in `410 Gone`, non-extendable, replacement named 90–120 days out).

**Research context.** The compliance side is understood; the security upside is the under-marketed part. `cross-cutting-gaps.md` states it directly: an air-gapped deployment **structurally eliminates the exfiltration chains** EchoLeak and the Slack AI attack both depend on, because the outbound channel does not exist — no-egress is a *retrieval-security primitive*, not just a checkbox, and it is the only mitigation in this dimension that removes a leg of the lethal trifecta rather than filtering it. The substrate is ready: five independent 2024–2026 works (EdgeRAG 2412.21023, MiniRAG 2501.06713 at *25% of the storage*, distributed RAG 2504.11197, on-device representation 2604.14403 at *1/10 of the context*, FD-RAG 2605.27432 at *8.4× lower latency*) all trade precomputation for on-demand compute, plus embedded stores (sqlite-vec, ~8k stars, pre-v1) and permissively licensed 149M–311M-parameter long-context encoders (`granite-embedding-311m-multilingual-r2`, Apache-2.0, 32k positions, verified from `config.json`) that show the embedding and reranking stages need not be hosted at all. `private-federated-personalized.md` adds the tier structure: TEEs at **<10% overhead** (arXiv 2410.05930) as the pragmatic middle, cryptographic retrieval at 4×–190× (arXiv 2608.01192) reserved for query-privacy-critical sources. What no framework does is let *policy*, not code, choose the tier.

**Next-gen requirement.** Egress is an explicitly declared capability, verifiable at runtime. Testable: (a) a `no-egress` profile in which any outbound network call from any component — including a nested, lazily-resolved one — raises rather than falling back, asserted by a test that runs the full pipeline with the loopback interface only and a stale API key present in the environment; (b) no implicit global provider resolution: an unconfigured LLM/embedder is an error, never a hosted default; (c) telemetry is opt-in, and the framework ships a test asserting the emitted payload matches its documented schema field-for-field (the exact failure Khoj shipped for years); (d) every configured knowledge source declares a data-residency and trust tier that the retriever enforces, and a source outside the declared compliance boundary is refused, not warned about; (e) connector capability changes require re-consent — a connector whose declared scopes or injected instructions change is quarantined until re-approved; (f) a bundled open-weight embedder makes the no-egress profile actually usable, so it is a supported mode rather than a theoretical flag.

## Near-misses

Patterns that did not clear the bar, kept here so the synthesis is auditable.

- **Embedding inversion as a *framework* failure (2 platforms + strong research).** vec2text's 92%-exact-recovery result is peer-reviewed and OWASP LLM08 now names embedding inversion explicitly, but the *framework* corpus contains almost no evidence of anyone treating vectors as sensitive. The only platform-level traces are LlamaIndex #20912 (private *vectors* silently shipped to a hosted API) and the general practice of third-party managed vector hosting. This is a real hazard with an inference-grade framework record; it belongs in the paper as a design premise (classify the index at source sensitivity), not as an observed cross-framework failure.
- **Membership inference and query-privacy leakage (0 platforms).** arXiv 2405.20446 shows corpus membership is inferable from outputs, and set membership is itself confidential in regulated domains. No framework in the corpus mentions it; no rate-limiting or probing defense appears anywhere. Genuinely unaddressed rather than mishandled.
- **Feedback-channel poisoning (0 platforms, by construction).** `cross-cutting-gaps.md` (b) notes that if a RAG system *did* learn from clicks, poisoning would extend into the ranker. Since no framework closes the feedback loop at all, this is a hazard of the *next* generation, not a failure of this one — worth stating as a design constraint on any learned-ranking proposal.
- **Corpus-integrity/retraction tracking (1 vertical, 0 general frameworks).** `medical-vertical-rag.md` documents retracted-article citation as a live harm with a benchmark (Pub-Guard-LLM) and a 91.9%-catch-rate biomedical-KG poisoning screen. No general framework has a retraction or withdrawal concept. Folded into SG-7 as a requirement rather than raised as an observed cross-framework pattern.
- **Model/license governance traps (1 vendor).** NVIDIA's ViDoRe-topping `llama-nemoretriever-colembed-3b-v1` ships under the **non-commercial** `customized-nscl-v1` license while the commercial alternative is a different, smaller model — a real procurement hazard where "cite the leaderboard in the architecture review" produces an unshippable design. One vendor; recorded, not generalized.
- **Fabricated personal data as a privacy harm (1 platform).** Mem0 #4573's 5.2% hallucinated-user-profiles category is a distinct category of harm — manufactured personal data about identifiable subjects, retrieved later as fact — that no framework has a concept for. Referenced inside SG-7; too thin alone.
- **Business-continuity as a governance risk (1 file, 4 platforms).** Flowise EOL Aug 31 2026 post-acquisition, Langflow's dependence on IBM/DataStax, Dify's source-available license permitting stricter terms later. Real, and it is governance in the procurement sense, but it is a *market* risk rather than a security-control failure; it belongs in a different dimension.
- **Non-determinism as an audit failure (landscape-heavy).** Microsoft's *"precise reconstruction of a query or response isn't guaranteed"* plus LLM planning, parallel merge order, semantic caching, and silent platform-side ranker changes make retrieval irreproducible in principle. The framework-side evidence is one clean case (NVIDIA E3), so this is folded into SG-5 rather than standing alone.

## Dimension synthesis: why the ecosystem is stuck here

**Every issue above is an ownership gap, not a knowledge gap — and the corpus proves it in the vendors' own accounting.** `cross-cutting-gaps.md`'s ownership table scores the security-relevant rows the same way: a standard or a research result exists (OWASP LLM08, GDPR Art. 17, EU AI Act, CaMeL, SD-RAG), and the framework primitive is **No**. Six of eight cross-cutting categories are non-adoption. The defences are not merely known, they are *priced*: CaMeL buys provable injection resistance for ~7 utility points; TEEs cost <10% overhead; SD-RAG reports ~58% privacy improvement by moving policy into the retriever. Continued reliance on classifier-based filtering at 11.3% residual ASR is a choice.

**The dimension's four root causes are structurally distinct, which is why point fixes fail.**

1. **A type signature that cannot express the requirement.** `retrieve(query, k) -> docs` has no slot for a principal, a policy, a trust label, a privacy budget, or an audit handle. Every failure in SG-1, SG-2, SG-5, and SG-7 is downstream of that one omission, which every framework inherited from single-corpus academic IR. You cannot bolt authorization onto a function that has no notion of who is calling — the metadata filter *is* what bolting it on looks like, and SG-2 is what happens next.
2. **Open-core economics put the security boundary exactly where the paywall is.** Haystack (RBAC = Enterprise), Onyx (permission sync = Cloud/EE), Bedrock (document ACLs = Managed tier), Databricks ("implement at the application layer"), Kendra ("customers are responsible"). Five independent teams drew the same line, and the perversity is systematic: **the most regulated customers — self-hosted, air-gapped, on-prem for statutory reasons — are exactly the ones the OSS tier denies authorization to.**
3. **The features that define a RAG framework are the features that define its CVE surface.** Template-rendered prompts, filter-to-query translation, pipeline serialization, arbitrary-document ingestion, inline code execution. SG-4's table spans 12 platforms and 40+ CVE/advisory IDs, and the vector is a *product differentiator* in nearly every case. That is why sandboxes keep arriving after exploitation (RAGFlow v0.25, Haystack 3.0, AI-Q's unchecked roadmap box): hardening the extension point is indistinguishable, from a roadmap's perspective, from removing the feature.
4. **Nothing in this dimension is measured, so nothing is prioritized.** There is no benchmark for ACL correctness, erasure verifiability, jamming resistance, provenance fidelity, or audit replayability. Meanwhile PoisonedRAG, AgentPoison, jamming, vec2text, and membership inference all publish quantified results that **no framework ships as a pre-deployment test**. `cross-cutting-gaps.md` states the mechanism plainly: *"You cannot put an unmeasured property on a roadmap."* Retrieval leaderboards move on nDCG; a framework that shipped verifiable erasure would show up on no chart at all.

**The issues in this dimension are coupled, and each coupling crosses an ownership boundary.** This is the concrete form of the argument for one framework rather than eight libraries.

| Coupling | Mechanism | Owners who each see only one end |
|---|---|---|
| SG-1 → SG-2 | With no principal in the signature, authorization must be smuggled in as a metadata filter — so a relevance bug becomes an authz bug | framework maintainer / store integrator |
| SG-2 → SG-4 | Filters are serialized to SQL/OData/Cypher by string construction, so the isolation channel is also the injection channel (CVE-2025-67644, CVE-2025-29189, R2R #2290) | store integrator / security team |
| SG-5 ↔ retrieval quality | Tombstone debt is simultaneously a compliance liability and a recall regression (Qdrant: disconnected graph components), so high-churn regulated corpora silently degrade | vector-DB team / compliance |
| SG-5 → SG-7 | Erasure cannot be proven without a retrieval record, and a retrieval record is impossible without provenance that survives compression | compliance / product UX |
| SG-3 → SG-7 | Content-innocent attacks (83.3% ASR, all claims true) make content-based detection structurally useless, so the trust label must attach to the source | ML security / ingestion |
| SG-8 → SG-3 | No-egress removes leg 3 of the lethal trifecta, so a compliance control is the strongest available injection defense | infra / security |
| SG-6 → SG-1 | Governance sold by the platform team, implemented (or not) by the feature team; only the pitch is customer-facing | sales / engineering |
| SG-8 → SG-5 | A hosted embedder surrenders the migration clock, and a forced re-embed reads to a regulator as a *"significant change in design"* | procurement / legal |

**The compositional character of this dimension is its signature.** Nearly every serious incident is a composition of individually-correct parts. EchoLeak: retrieval scope is correct, instruction-following is correct, the composition is a 9.3. Slack AI: "intended." IBM's mangled signed URLs: the model correctly summarized text that happened to be a credential. Tombstones: the vector DB is correct about segments, the compliance team is correct about erasure, and together they produce recoverable "deleted" data that also degrades recall. Cross-tenant leaks: the filter DSL is correct, the backend translator is correct-ish, and `.isNotIn` at the end of a chain matches everything. Each seam crosses an ownership boundary that guarantees no component team will fix it — which is precisely the layer a framework occupies.

**Three things are genuinely unsolved, and the paper should say so.** (i) **Content-innocent attacks**: salience induction at 83.3% ASR with every claim true, and metadata impersonation with no imperative present, defeat fact-checking and injection detection *structurally*; the best published defence leaves 15.3–23.6%. This is why trust must attach to the **source**, not be inferred from content. (ii) **Verified deletion in ANN indexes**: no production HNSW/IVF design offers cryptographic or auditable erasure; hnswlib's request has been open since 2018. (iii) **Query privacy under agentic iteration**: cryptographic retrieval prices a *single* query at 4×–190×, an agent issues twenty adaptive ones, and the adaptivity itself is a side channel — with lower-bound work suggesting the floor is structural.

**The clock has run out, which is the strongest argument available.** As of 2 August 2026 the EU AI Act's main body applies; its audit, documentation, and data-governance obligations bind the retrieval layer of every high-risk deployment, and they must be satisfied using framework primitives that do not exist. The grandfather clause is a trap of its own — *"significant changes in their designs"* is exactly what a forced re-embed after a vendor's 18-month retirement clock looks like to a regulator. Meanwhile 21 U.S.C. §360j(o)(1)(E)(iii) already writes a retrieval-architecture requirement into statute: the clinician must be able to *independently review the basis* for a recommendation. **This dimension is the one where a next-generation framework's contribution is not an accuracy improvement but a viability argument** — the things a datastore can offer that parametric memory cannot (per-item licensing, attributable removal, principal-scoped disclosure, replayable audit) are the entire case for retrieval-centric architecture, and today not one of them is implemented well enough to survive an audit.
